Setting Up a Local RHEL 9 Repository Server — Complete Guide

rhel dnf apache selinux

In many organizations, each and every RHEL client machine hitting the Red Hat CDN directly for updates is neither efficient nor good practice — internet bandwidth gets consumed unnecessarily, and patching a large fleet takes much longer than it should. The proper solution for this is to set up one local mirror server which syncs the BaseOS and AppStream repositories once, and all the client machines pull updates from that server over the LAN itself. This is much faster, and also gives better control over what gets patched and when.

Below is the complete, tested procedure I follow for standing up such a local RHEL 9 repo server — from registering the mirror with Red Hat, right up to scheduling an automatic weekly sync. Kindly note this needs an active Red Hat subscription attached to the mirror server; without that, subscription-manager and dnf reposync will not be able to pull anything from the CDN.

Sizing the mirror server

Before starting, it is good to know what resources are needed. The table below gives the minimum and the recommended values I would suggest going with:

ResourceMinimumRecommended
CPU2 vCPUs4 vCPUs
RAM2 GB4 GB
Disk80 GB free150 GB free
Network100 Mbps1 Gbps

With --newest-only (only the latest package versions, not every historic version), BaseOS takes roughly 10–15 GB and AppStream another 15–20 GB — so around 25–35 GB total. Plan disk accordingly, keeping some headroom for future growth.

1. Register the mirror server with Red Hat

First step is registering the mirror server itself with the Red Hat Customer Portal, so it gets access to the CDN: 

bash
subscription-manager register --username=<rh-username> --password=<rh-password>

Attach an available subscription automatically:

bash
subscription-manager attach --auto

Then verify that registration is proper:

bash
subscription-manager status

You should be getting output like this, confirming everything is in order:

output
+-------------------------------------------+
   System Status Details
+-------------------------------------------+
Overall Status: Current

2. Install the required packages

bash
dnf install -y httpd createrepo_c dnf-utils policycoreutils-python-utils
PackagePurpose
httpdApache HTTP server, to serve the repo files to clients
createrepo_cGenerates the RPM repository metadata
dnf-utilsProvides the dnf reposync command
policycoreutils-python-utilsManages SELinux file contexts

3. Enable the RHEL 9 repositories

First check which repositories are available for RHEL 9 on your subscription:

bash
subscription-manager repos --list | grep "rhel-9"

Then enable the two we actually need — BaseOS and AppStream:

bash
subscription-manager repos \
  --enable=rhel-9-for-x86_64-baseos-rpms \
  --enable=rhel-9-for-x86_64-appstream-rpms

Confirm they got enabled properly:

bash
subscription-manager repos --list-enabled

4. Create the directory structure

bash
mkdir -p /var/repos/rhel9/baseos
mkdir -p /var/repos/rhel9/appstream

After the sync completes, the structure will look as below:

tree
/var/repos/
└── rhel9/
    ├── baseos/
    │   ├── Packages/
    │   └── repodata/
    └── appstream/
        ├── Packages/
        └── repodata/

5. Sync packages from the Red Hat CDN

This is the main step — pulling down the actual packages. --newest-only keeps only the latest version of each package (much less disk usage), and --delete removes any local packages that Red Hat has since retired from the CDN, so the mirror doesn't drift out of sync over time.

Sync BaseOS:

bash
dnf reposync \
  --repoid=rhel-9-for-x86_64-baseos-rpms \
  --download-path=/var/repos/rhel9/baseos/ \
  --newest-only \
  --delete

Sync AppStream:

bash
dnf reposync \
  --repoid=rhel-9-for-x86_64-appstream-rpms \
  --download-path=/var/repos/rhel9/appstream/ \
  --newest-only \
  --delete
Please note: the very first sync can easily take 30–90 minutes, depending on your internet speed and how busy the Red Hat CDN is at that time. Do not panic if it looks slow — just let it complete.

6. Generate the repository metadata

Once the packages are synced, we need to generate repodata/ — this is what the client machines actually read to resolve dependencies: 

bash
createrepo_c /var/repos/rhel9/baseos/
createrepo_c /var/repos/rhel9/appstream/

For all the subsequent syncs, use --update instead — much faster, as it only regenerates the metadata that actually changed:

bash
createrepo_c --update /var/repos/rhel9/baseos/
createrepo_c --update /var/repos/rhel9/appstream/

7. Configure the Apache HTTP server

Symlink the repo directory so Apache can serve it out:

bash
ln -s /var/repos /var/www/html/repos

Enable and start Apache:

bash
systemctl enable --now httpd

Check it is running fine:

bash
systemctl status httpd

And test locally that the repo is actually reachable:

bash
curl -s http://localhost/repos/rhel9/baseos/repodata/repomd.xml | head -5

Expected output should begin like this:

xml
<?xml version="1.0" encoding="UTF-8"?>
<repomd xmlns="http://linux.duke.edu/metadata/repo" ...>

8. Configure SELinux and the firewall

This step is very important and often gets missed — even if Apache is running fine, clients will get a 403 Forbidden if SELinux context is not set correctly on the repo directory.

SELinux:

bash
semanage fcontext -a -t httpd_sys_content_t "/var/repos(/.*)?"
restorecon -Rv /var/repos

Verify the context got applied:

bash
ls -lZ /var/repos/

It should be showing httpd_sys_content_t against the files.

Firewall:

bash
firewall-cmd --permanent --add-service=http
firewall-cmd --reload

Confirm the rule got added properly:

bash
firewall-cmd --list-services

9. Configure the client machines

On each RHEL 9 client, create a new repo file:

bash
vi /etc/yum.repos.d/local-rhel9.repo

Paste in the following, replacing <mirror-server-ip> with the actual IP or hostname of your mirror server:

ini
[local-rhel9-baseos]
name=Local RHEL 9 BaseOS
baseurl=http://<mirror-server-ip>/repos/rhel9/baseos/
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-redhat-release

[local-rhel9-appstream]
name=Local RHEL 9 AppStream
baseurl=http://<mirror-server-ip>/repos/rhel9/appstream/
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-redhat-release

Clear the DNF cache and check that the repos show up:

bash
dnf clean all
dnf repolist

You should be seeing:

output
repo id                   repo name
local-rhel9-baseos        Local RHEL 9 BaseOS
local-rhel9-appstream     Local RHEL 9 AppStream

Test an actual install from the local repo, purely to confirm end-to-end:

bash
dnf install --disablerepo="*" --enablerepo="local-rhel9-*" vim -y

10. Automate the repository sync

No need for a separate script — the sync and metadata commands can go directly into the cron file. Create it: 

bash
vi /etc/cron.d/rhel9-repo-sync

cron
# /etc/cron.d/rhel9-repo-sync
0 2 * * 0  root  dnf reposync --repoid=rhel-9-for-x86_64-baseos-rpms --download-path=/var/repos/rhel9/baseos/ --newest-only --delete && createrepo_c --update /var/repos/rhel9/baseos/
0 2 * * 0  root  dnf reposync --repoid=rhel-9-for-x86_64-appstream-rpms --download-path=/var/repos/rhel9/appstream/ --newest-only --delete && createrepo_c --update /var/repos/rhel9/appstream/

Verify the cron job got registered:

bash
crontab -l -u root

And after the first scheduled run on Sunday, check /var/log/cron to confirm it actually ran:

bash
grep reposync /var/log/cron

A few commands that are useful to check the health of the mirror server:

Setup checklist: mirror registered and subscription attached, packages installed (httpd, createrepo_c, dnf-utils), BaseOS/AppStream repos enabled, directories created under /var/repos/rhel9/, dnf reposync and createrepo_c completed for both, Apache symlink and service started, SELinux context applied, firewall opened for HTTP, client .repo file in place and dnf repolist confirmed, and the cron sync job scheduled.

That completes the setup. Once this is in place, patching a large fleet of RHEL 9 machines becomes much quicker and much lighter on your internet line — every client pulls from the LAN mirror instead of going out to the CDN individually, and the weekly cron job keeps the mirror current without any manual intervention needed.
